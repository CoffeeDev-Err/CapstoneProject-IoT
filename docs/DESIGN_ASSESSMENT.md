# GeoSentri Prototype Design Assessment

The following table documents the design improvements applied to the GeoSentri supervisor web dashboard and officer mobile application.

| Component / Element | Before | After |
|---|---|---|
| **1. Color Scheme and Consistency** | The prototype used several unrelated accent colors, including blue, purple, green, amber, and red. Similar actions and statuses were represented differently across the web and mobile interfaces. | A consistent semantic palette is applied. Blue shades are used for branding, navigation, primary actions, and normal operations; neutral colors are used for text, backgrounds, borders, and inactive states; and red is reserved for emergencies, danger, destructive actions, and boundary violations. |
| **2. Typography and Readability** | Page titles, section headings, body text, and supporting descriptions did not always have a clear and consistent hierarchy. Repeated descriptions also added unnecessary visual noise. | A consistent typographic hierarchy distinguishes page titles, section headings, body content, labels, and supporting text. Duplicate descriptions were removed, and concise wording improves readability and allows users to scan important information more quickly. |
| **3. Layout and Spacing** | Some sections used large containers, inconsistent spacing, and repeated content, making screens appear crowded or unnecessarily complex. | Related information is grouped into clearly defined sections with consistent spacing, alignment, control sizing, and card treatment. Unnecessary containers were removed to create a cleaner and more organized interface. |
| **4. Navigation and Page Labeling** | The interface retained the former BantayCabagan name and included labels such as “Supervisor Deployment Assignment,” which were longer or more technical than necessary. | The product is consistently presented as **GeoSentri** under the **Philippine National Police**. Navigation items and page labels use concise, task-oriented wording such as **Account Management** and **Assign Area**, making their purpose easier to understand. |
| **5. Forms and Input Controls** | The profile-photo field used a large upload container, repeated file instructions, and form content that increased visual clutter. Account fields were also less direct to review and maintain. | The photo field is simplified to a clear **Choose Photo** button with concise file guidance. Duplicate instructions are removed, related fields are grouped logically, and authorized users can maintain personnel identity, login, email, password, role, and assignment details through Account Management. |
| **6. Marker Colors and Iconography** | Personnel marker colors were inconsistent. On-duty officers could appear green or purple, while some critical or boundary states used colors that did not clearly communicate urgency. | Marker colors now have consistent operational meaning: royal blue (`#2563EB`) indicates on-duty personnel, cyan-blue (`#38BDF8`) indicates an active operation responder, and red (`#DC2626`) indicates an emergency requester or personnel outside the Cabagan boundary. The current mobile user is identified by a white outer ring. |
| **7. Alerts and System Feedback** | Routine activity and critical events did not always have enough visual distinction, making emergencies and backup requests more difficult to identify immediately. | Emergency, backup-request, and boundary-violation markers use a red ring and pulse animation. Responding personnel remain cyan-blue, allowing users to distinguish the person requiring assistance from the officers responding to the event. Notifications and status messages provide additional textual feedback. |
| **8. Map Interaction and Motion** | Personnel markers moved abruptly whenever new GPS coordinates were received. Map viewing options were also more limited, particularly on mobile. | Confirmed GPS coordinates are connected using a responsive 700-millisecond ease-out animation, reducing abrupt visual jumps without predicting unreported locations. The mobile map also provides street, satellite, and optional 3D views with responsive pan and zoom controls. |
| **9. Information Density and Marker Clustering** | When several officers were positioned close together, their photo markers overlapped and could hide identities, locations, and operational statuses. | Nearby personnel are combined into numbered clusters to reduce overlap. Cluster colors reflect the highest-priority member status, selecting a cluster zooms toward its members, and individual photo markers reappear at closer zoom levels. |
| **10. Responsive Design and Accessibility** | Dense content, overlapping controls, and similar visual emphasis could make the system more difficult to use on smaller screens or during time-sensitive operations. | Layouts adapt to web and mobile screen sizes, the web monitoring panel can be collapsed to provide more map space, mobile controls use appropriate touch-target sizes, and interface elements include clear labels. Color is supported by text, marker rings, numbering, and animation so that status is not communicated by color alone. |

## Color Palette Reference

| Color Family | Application |
|---|---|
| **Blue** | Branding, navigation, primary actions, on-duty personnel, and active operations |
| **Neutral** | Text, backgrounds, surfaces, borders, disabled controls, and stale or inactive information |
| **Red** | Emergencies, danger, destructive actions, backup requests, and boundary violations |

Navy blue, royal blue, light blue, and cyan-blue are treated as shades of the blue family. White, black, gray, and slate are treated as neutral colors. Natural colors contained in street or satellite basemap imagery and user-uploaded photographs are considered content and are not counted as interface palette colors.
